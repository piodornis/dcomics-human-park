# Canon Review Protocol

## Classification rules

### CANON
Use only for explicitly accepted facts in current authoritative project material.

### INFERENCE
Use when a conclusion follows logically from canon but is not explicitly confirmed. State the supporting facts.

### PROPOSAL
Use for new creative solutions, reinterpretations, retcons, or scene ideas that are not accepted yet.

### CONFLICT
Use only when two claims cannot both be true under the current interpretation.

### OPEN
Use for missing, deliberately unresolved, or authority-ambiguous information.

## Absence is not contradiction

If canon says nothing about an event, relationship, date, or trait, do not label a new claim as conflict merely because it is new. Mark it `PROPOSAL` or `OPEN` depending on context.

## Draft versus canon

A planned scene may contradict canon without creating a canon-to-canon contradiction. Report this as a proposal conflict and identify that the established canon remains intact.

## Relative chronology

When exact dates are unknown, compare relative ordering instead of inventing dates.

Useful checks:

- before / after
- already active / not yet created
- injury present / healed / not yet sustained
- relationship phase at that point in the story
- knowledge available to the character at that time

## Relationship consistency

Check both perspectives. A relationship may legitimately be asymmetric.

Do not mark different emotional interpretations as conflict unless both files make incompatible factual claims.

## Character consistency

A character may behave unusually without creating a canon conflict. Distinguish:

- contradiction of established fact,
- plausible character development,
- unexplained deviation,
- deliberate deception,
- unreliable narration.

Unexplained deviation is usually `NOTE` or `OPEN` before it becomes `CONFLICT`.

## World-rule consistency

Treat explicit world rules as hard constraints unless the project states exceptions exist.

When a proposed event violates a rule, report whether the conflict can be solved by:

1. changing the proposal,
2. establishing an exception,
3. revising the rule,
4. revealing incomplete character knowledge.

## Canon revision

A deliberate retcon is allowed. The Guardian's job is to expose its impact.

When canon is revised, identify likely dependencies in:

- character profiles
- relationships
- timeline
- world rules
- story arcs
- issue scripts
- visual continuity
