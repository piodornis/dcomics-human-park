# Character Record Schema

## Inhalt

- [Standardstruktur](#standardstruktur)
- [Regeln](#regeln)

Dieses Schema ist die Standardstruktur für aktualisierte Charakterakten. Bestehende Projektstrukturen haben Vorrang, wenn sie bereits konsistent und ausreichend vollständig sind.

## Standardstruktur

```markdown
# [Charaktername]

## Status
- Character ID: [stabile ID, falls vorhanden]
- Version: [bestehende Projektkonvention oder Datum]
- Canon status: current
- Last updated: [YYYY-MM-DD]

## Kurzprofil
Kurze, präzise Zusammenfassung der Figur und ihrer erzählerischen Funktion.

## Identität
- Vollständiger Name:
- Rufname / Alias:
- Alter / Geburtsdatum:
- Herkunft:
- Beruf / Rolle:
- Zugehörigkeiten:

## Erscheinungsbild
- Körperbau:
- Gesicht / markante Merkmale:
- Haare:
- Kleidung:
- Wiederkehrende Accessoires:
- Besondere visuelle Konstanten:
- Erlaubte Variationen:

## Persönlichkeit
- Dominante Eigenschaften:
- Werte:
- Stärken:
- Schwächen:
- Ängste:
- Bedürfnisse:
- Innere Widersprüche:

## Motivationen
### Kurzfristige Ziele
...

### Langfristige Ziele
...

### Tieferliegende Bedürfnisse
...

## Hintergrundgeschichte
Chronologisch strukturierte, kanonische Biografie. Unsichere Angaben nicht hier als Tatsache formulieren.

## Beziehungen
### [Figur / Gruppe]
- Art der Beziehung:
- Gemeinsame Geschichte:
- Aktueller Zustand:
- Konflikt / Spannung:
- Abhängigkeit oder Machtverhältnis:

## Fähigkeiten und Grenzen
- Fähigkeiten:
- Wissen:
- Ressourcen:
- Grenzen / Verwundbarkeiten:

## Sprache und Verhalten
- Sprachstil:
- Typische Verhaltensweisen:
- Körpersprache:
- Wiederkehrende Eigenheiten:

## Character Arc
- Ausgangszustand:
- Zentrale innere Frage:
- mögliche Entwicklung:
- bereits kanonisch erreichte Wendepunkte:

## Kontinuitätsnotizen
Nur belegte Hinweise, die für spätere Szenen wichtig sind.

## Offene Punkte
### INFERENCE
- ...

### PROPOSAL
- ...
```

## Regeln

- CANON bevorzugt in die regulären Sachabschnitte integrieren.
- INFERENCE und PROPOSAL nicht so formulieren, als seien sie kanonische Fakten.
- Offene Widersprüche im Abschnitt `Offene Punkte` dokumentieren oder separat im Review ausgeben.
- Eine neue Fassung soll vollständig lesbar sein; keine reine Patch-Liste erstellen.
- Keine unnötigen Felder erzwingen, wenn sie für die Figur nicht relevant sind.
